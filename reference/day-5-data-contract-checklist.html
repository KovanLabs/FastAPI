Day 5 reference

Deterministic order processing

A contract checklist for keeping cleaning, schema validation, business validation, duplicate detection, and output writing separate and auditable.

Stage contract

parsed object → deterministic cleaner → Pydantic schema validation → business validation → duplicate decision → exactly one accepted/rejected NDJSON write → reconciled counters

This order is provisional until the duplicate policy says whether structurally invalid records reserve their identifiers. That is a business decision, not a Pydantic decision.

Field policy columns

ColumnQuestion it must answer
Field/pathWhich exact scalar or nested value does the rule govern?
Accepted raw formsWhich JSON types and textual forms are admitted before schema validation?
Missing/null/blankAre these three states distinct, rejected, or normalized?
CleaningWhat deterministic transformation is applied? “None” is a valid policy.
Canonical outputWhat exact Python/JSON representation leaves the cleaner?
Reject codeWhich stable project-owned code is emitted when the policy fails?
AuthorityRequirement, approved business decision, or still an open question?

Rejection catalogue columns

ColumnQuestion it must answer
Stable codeWhat machine-readable identifier remains stable when human wording changes?
StageParse, clean, schema, business, duplicate, or write?
LocationHow are nested fields and list indexes represented without losing structure?
TriggerWhat exact predicate produces this rejection?
Public messageWhat safe, readable explanation is emitted?
Audit dataWhich record number, source identity, duplicate-first occurrence, or raw fragment is retained?

Required evidence

  • Parameterized examples for every cleaning rule and no-op case.
  • clean(clean(x)) == clean(x) for every accepted cleaner input.
  • Nested error locations preserved as segments such as ("items", 0, "sku").
  • Duplicate tests spanning records, batches, and the declared import/job scope.
  • total == accepted + rejected and output-line counts equal their counters.
  • Measured peak memory for the in-memory duplicate index at realistic cardinality.
  • A frozen standard-library Python golden input, accepted output, rejected output, and summary.
