Lesson 8 · Day 6 · Bounded memory

Replace sorting with an ordered-input contract

The safe change is not simply deleting sort(). First make ordering an input invariant, prove violations fail closed, and only then let both adapters stream without retaining the dataset.

Day 5 ordered accepted.ndjson → verify strict increase → scan/write each record → bounded working set
Repository fact: Day 5 publishes rows with ORDER BY records.record_number. Accepted records are a subset of those uniquely numbered source rows, so their numbers are strictly increasing.

1. Change the contract before the implementation

The adapter input contract becomes: every line is a canonical accepted envelope, and each record_number is greater than the preceding one. A duplicate or smaller number is an adapter input failure.

previous_record_number: int | None = None

for line in source:
    record = _canonical_envelope(json.loads(line))
    current = record["record_number"]
    if previous_record_number is not None and current <= previous_record_number:
        raise AdapterExecutionError(
            "record_number must be strictly increasing"
        )
    previous_record_number = current
    yield record

Strictly increasing means both conditions fail:

1, 3, 2  # out of order
1, 2, 2  # duplicate

3. Stream in Standard Python

Remove the list comprehension and records.sort(...). Open the destination exclusively, then validate, canonicalize and write one source line at a time. Keep the existing fail-closed cleanup so a bad later line removes the partial result.

with input_path.open("r", encoding="utf-8") as source:
    with temporary_output_path.open("x", encoding="utf-8", newline="\n") as destination:
        for value in _iter_canonical_records_in_order(source):
            destination.write(json.dumps(
                value,
                ensure_ascii=False,
                separators=(",", ":"),
            ))
            destination.write("\n")
            records_written += 1

Only the current line and current canonical record remain live. The complete dataset is no longer stored in a Python list.

4. Remove the Polars sort

Keep the exact-type preflight, but make it verify strict ordering. Then remove only the sort node:

plan = pl.scan_ndjson(
    input_path,
    schema=CANONICAL_ACCEPTED_SCHEMA,
    ignore_errors=False,
)
plan.sink_ndjson(
    temporary_output_path,
    maintain_order=True,
    engine="streaming",
)

maintain_order=True now preserves the already-approved source order. It does not sort the records.

Trade-off: unordered canonical NDJSON is no longer repaired by Day 6. It is rejected. That is deliberate: Day 5 owns canonical staging order, while Day 6 preserves and verifies it.

Retrieval check

Why can we not merely delete sort()?

Because an unordered input would then produce nondeterministic or contract-breaking output. Ordering must first become a validated precondition.

Why use <= instead of <?

Record numbers identify unique source positions, so equal adjacent numbers are invalid as well as decreasing numbers.

What should the new physical plan show?

An NDJSON scan flowing to the NDJSON sink, with no global sort node.
