Lesson 1 · 10 minutes

Trace one request end to end

Your goal is to explain why the same request touches main.py, api/, schemas/, services/, and core/.

The request

POST /orders/validate
Content-Type: application/json
X-Request-ID: req-123

{
  "order_id": "ORD-7",
  "customer_email": "buyer@example.com",
  "amount": "1299.50",
  "currency": "INR",
  "ordered_at": "2026-09-22T10:30:00+05:30",
  "status": "completed",
  "items": [{"sku": "LAPTOP-01", "quantity": 2}]
}

The seven hand-offs

  1. Uvicorn calls the ASGI app. RequestContextMiddleware.__call__ sees an HTTP scope, extracts X-Request-ID, and starts a timer.
  2. FastAPI matches the route. The router registered POST /orders/validate to validate_order.
  3. Pydantic builds OrderCreate. It converts JSON strings into EmailStr, Decimal, datetime, and OrderStatus, then enforces every Field constraint.
  4. FastAPI resolves the service dependency. get_order_validation_service first receives cached Settings, then constructs the service with its supported currencies. FastAPI's dependency system is designed to resolve this graph automatically.
  5. The service applies the business rule. It checks whether INR belongs to the configured immutable set. If so, it returns OrderResponse.
  6. The response model enforces the public contract. FastAPI validates, serializes, and filters the result through OrderResponse; response models also drive OpenAPI documentation.
  7. The middleware finishes the response. Its wrapped send adds X-Process-Time and echoes X-Request-ID.
Why so many files? Each layer has one reason to change. HTTP routing can evolve without moving the currency rule; the currency rule can evolve without changing how settings load; request fields can evolve without rewriting middleware.

Now run the failure path mentally

Change "currency": "INR" to "currency": "JPY".

OrderValidationService.validate → raises UnsupportedCurrencyError → FastAPI finds application_error_handler(ApplicationError) → handler reads status_code=422, error_code, message, details → handler reads request.state.request_id set by middleware → JSONResponse returns the stable error envelope → middleware still adds response headers

The route does not catch the exception. That is intentional: one global exception handler keeps every application error consistent.

Retrieval check

Answer before opening each explanation.

Which layer decides whether “JPY” is supported?

The service layer: OrderValidationService.validate. Pydantic only checks that the currency string is exactly three characters.

Why is SettingsDependency an Annotated alias?

It preserves Settings as the real type while attaching Depends(get_settings) metadata once for reuse.

Where does the request ID live during the request?

In the ASGI scope's state dictionary, surfaced by FastAPI as request.state.request_id.

Why use a response model when the service already returns OrderResponse?

It enforces the HTTP boundary, generates an OpenAPI schema, serializes supported types, and filters unexpected fields even if a replacement service returns extra data.
