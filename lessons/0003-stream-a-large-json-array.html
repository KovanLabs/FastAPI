Lesson 3 · Day 4 · standard JSON

One large array, one order at a time

The production input is a standard JSON array. This lesson traces every logical line in the bounded reader, state machine, summary, API route, and comparison script—and explains why each belongs there.

UploadFile → stored .json file → read(64 KiB) → parser state machine → one Python value → object classification → bounded summary → Swagger response

1. The public iterator

Open app/core/parsers.py and find iter_json_array and iter_file_chunks.

parser = _IncrementalArrayParser(...)Creates one stateful parser for the complete document.State must survive from one chunk to the next.

2. Parser state: memory carried between chunks

FieldMeaningWhy needed
self._maxMaximum raw bytes allowed for one array element.One enormous order must not grow memory without a bound.
self._bufferBytes still needed to build the current element.An order may start in one chunk and end in another.
self._stateOne of before_array, first_or_end, element_required, in_element, separator_or_end, or done.Explicit grammar states prevent missing, doubled, or trailing commas from being accepted.
self._positionIndex of the next byte that has not been scanned.Retained bytes must not be scanned and counted twice.
self._startIndex where the current element begins.The exact byte slice is passed to json.loads.
self._structuredWhether the element begins with { or [.Containers end by balanced nesting; scalars end at the array delimiter.
self._depthNumber of unmatched container openings inside the element.A comma inside nested items is not an order separator.
self._in_stringWhether scanning is currently inside JSON quotes.Braces and commas inside text are data, not structure.
self._escapeWhether the preceding character was \.An escaped quote \" must not close the string, even across chunks.

3. Every parser transition

State/codeWhat happens and why
feed(chunk)Requires bytes, appends them to the retained buffer, then scans. Binary input avoids accidental text decoding at the transport boundary.
before_arraySkips JSON whitespace and requires [. Our contract is a top-level array, not one object or NDJSON.
first_or_endAllows either the first element or ] for an empty array. A comma here means an element is missing.
element_requiredEntered after a comma. Unlike the first state, ] is rejected, which catches a trailing comma.
self._start = iMarks the first byte of the element so the exact raw size and JSON slice are known.
self._structured = ch in b"{["Selects container-boundary tracking for objects and nested arrays.
self._check_size(1)Counts the first byte immediately; a zero-byte maximum rejects any element.
separator_or_endAfter a complete value, only whitespace, a comma, or the array’s ] is legal.
doneAfter ], only whitespace is accepted. Other content is trailing garbage and invalidates the document.
not structured ... ch in b",]"A top-level scalar ends at an array delimiter. It is still parsed as valid JSON and later classified as not_object.
_check_size(i - self._start + 1)Checks the growing raw element before accepting the current byte.
if self._in_stringUpdates escape/string state and ignores structural-looking characters until the string closes.
ch in b"{[" / ch in b"}]"Increments/decrements nesting. Depth zero means the outer element container is complete.
_emit(records, end)Copies only the completed element bytes, strips surrounding whitespace, checks size, and calls json.loads.
except (JSONDecodeError, UnicodeDecodeError)Maps malformed JSON or invalid encoded bytes to the application’s stable invalid_json error.
del b[:removed]Discards bytes that can no longer be needed. When an element is incomplete, only bytes before its start are discarded.
finish()Requires that [ was seen, no element remains incomplete, and the state reached done. EOF alone never closes JSON.

Python JSON’s “Basic Usage” documents loads; JSONDecodeError represents invalid JSON syntax.

6. Why compare with ijson and json.load?

The comparison script is scripts/compare_json_memory.py, and the recorded results are in the Day 4 evidence note.

Line/conceptWhy
json.load(source)Parses the complete document and returns the full top-level list: simple, but memory grows with the dataset.
ijson.items(source, "item")item selects each element of the top-level array and yields it incrementally.
sum(1 for _ in records)Consumes lazily and retains only a counter plus the current record.
len(list(records))Deliberately retains every result to demonstrate how the caller can destroy the parser’s memory advantage.
perf_counter()Measures elapsed wall-clock time.
resource.getrusage(...).ru_maxrssReports the process’s peak resident memory on this Linux development environment.

On the 100,000-order fixture, streaming custom/ijson iteration used about 18 MiB peak RSS. json.load used about 162 MiB, while converting the iterators to lists used about 175–178 MiB. The 10-million-order fixture was counted with ijson in 44.734 seconds at 18.51 MiB peak RSS on this machine. These values are measurements, not universal guarantees.

ijson’s official “High-level interfaces” describes continuous reads and items; its “Options” documents the 65,536-byte default buffer and number behavior. Python JSON documents load.

Recovery boundary

Policy: a valid JSON value that is not an object is a record-level not_object failure, and iteration continues. Broken commas, brackets, encoding, or element syntax invalidate the single enclosing JSON document, so parsing stops. NDJSON can recover line by line because every newline supplies an independent boundary; a JSON array cannot safely invent a boundary after broken syntax.

Retrieval check

Does 64 KiB mean one order per chunk?

No. It is a read size. A chunk may contain part of one order, one order, or many orders.

Why track _in_string?

Structural characters inside quoted text must be treated as data.

Why does list(iterator) raise memory use?

It retains every yielded object instead of releasing each after processing.

Where will Polars fit?

After parsing and validation, bounded groups of valid objects can become Polars DataFrames for cleaning. One all-record list would defeat today’s memory design.
