From an NDJSON path to a streaming result

This experiment separates four ideas: declaring the source path, declaring its nested schema, building a lazy query plan, and executing that plan with the streaming engine.

accepted.ndjson → explicit schema → LazyFrame plan → collect(engine="streaming") → DataFrame

Imports and input

from pathlib import PathImports Python’s path-object type.It avoids manual path-string joining and clearly marks the value as a filesystem path.

The explicit schema

CodeMeaningContract consequence
def build_schema() -> pl.SchemaDefines a function whose result is a Polars schema.The schema is reusable by the adapter and its tests.
pl.Schema({...})Maps each top-level JSON key to a Polars data type.We do not let a small input prefix decide the contract through inference.
record_number: pl.Int64Represents the source record number as a signed 64-bit integer.It can be used as the deterministic sort key.
order: pl.Struct({...})Models the nested JSON order object.Nested fields remain grouped under order instead of being flattened accidentally.
pl.StringKeeps canonical text fields as strings.In particular, amount and timestamp serialization are not reinterpreted by this experiment.
items: pl.List(pl.Struct(...))Models items as an ordered array of nested objects.The schema retains the list/struct shape produced by Day 5.
quantity: pl.Int64Models the canonical quantity as an integer.A schema mismatch is visible instead of intentionally ignored.

Build and execute the lazy plan

CodeWhen it actsWhat it proves
def main() -> NoneWhen main() is called.Groups the experiment without returning a value.
pl.scan_ndjson(...)Builds a lazy source node; it does not execute the complete query.The query optimizer can later push projections and predicates toward the scan.
schema=build_schema()During scan-plan construction.The expected nested types are deliberate rather than inferred.
ignore_errors=FalseDuring parsing when the plan executes.A schema parsing failure remains visible; Polars does not replace it with Null under the ignore-errors option.
collect_schema()Resolves the schema of the lazy result.It checks the planned column types, not the transformed data values or Day 5 business rules.
explain()Formats the optimized logical query plan.It shows what Polars plans to do, but it is not the streaming physical-plan evidence required at the milestone exit.
collect(engine="streaming")Executes the query.It asks Polars to use streaming execution and returns a materialized DataFrame. Unsupported operators may still fall back.
print(result)After execution completes.Lets us inspect the one canonical golden record during this small experiment.

The direct-execution guard

if __name__ == "__main__": is true when Python executes this file directly. It is false when another module imports the file. Therefore, main() runs for the terminal experiment without running automatically during an import.

What this experiment does not prove

  • It does not prove byte-for-byte equivalence; the adapter and shared serializer tests do that.
  • It does not prove every operation streamed; inspect the physical graph.
  • It does not prove bounded peak memory; measure process memory with a larger fixture.
  • It does not validate cleaning or business rules; Day 5 owns those stages.

Retrieval check

Which line actually executes the query?

collect(engine="streaming").

Why retain amount as a string?

The external canonical contract is "2.35"; this experiment must not silently change its representation.

Does requesting streaming prove every operator streamed?

No. Polars documents that unsupported operations can fall back to in-memory execution, so the physical plan and process memory must be inspected.
