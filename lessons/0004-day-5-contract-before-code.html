Lesson 0004 · Day 5

Contract before cleaner

Your first win is not a validator. It is a policy precise enough that two independent implementations produce byte-for-byte equivalent decisions.

  1. Cleaning policy + rejection catalogue
  2. Deterministic cleaner + idempotence
  3. Pydantic schema + nested errors
  4. Business rules + stable codes
  5. Import-scope duplicate index + memory
  6. Incremental NDJSON sinks + golden result

The boundary to learn

Pydantic behavior: a model or TypeAdapter produces an output conforming to declared types and constraints, and non-strict validation may convert input. Its structured errors include a machine-readable type and a nested loc.

Project behavior: trimming, case folding, blank handling, money scale and rounding, time-zone normalization, supported currencies, duplicate scope, winner policy, public error codes, and output envelopes are choices this project must own.

Do not infer that an email may be lowercased, that a naive datetime means UTC, that 1.239 should round to cents, or that the first duplicate wins. Each changes business meaning.

Milestone 1 exercise

Write one policy row for every path: order_id, customer_email, amount, currency, ordered_at, status, items, items[].sku, items[].quantity, and extra fields.

For each, state accepted raw JSON types, missing/null/blank behavior, exact cleaning, canonical output, stable reject code, and authority. Mark unknown requirements OPEN.

Then write the rejection catalogue for parse failure, non-object record, cleaning failure, schema failure, business failure, duplicate, and output failure. State whether one record can carry multiple issues and whether processing continues.

Why this precedes implementation

Pydantic’s model documentation explicitly distinguishes output conformance from input validity and documents coercion under “Data conversion”. The validators documentation says before validators receive raw input, while after validators receive the internally validated value. Those mechanics cannot decide your domain policy.
